# Datasets-space report delivery

This discovery mode targets the matching datasets space, not the curator's personal space or the main space. `preflight` checks the configured public editor's membership; actual signer capability and current proposal rules must also be checked through geo-publish before a write. Membership alone does not prove that this runtime can publish. Disabled spaces need a first-run checkpoint, full applicable criteria and retrieval/access verification before activation.

Use geo-publish for schema/typed-create/semantic-duplicate checks, dry-run operations, explicit human gate and readback. Read ontology-advisor when choosing a report model. Inspect existing report pages and the target-space schema first. A personal-space Review finding prototype is precedent, not proof that its custom types/properties are available in each destination. Prefer an existing compatible model; do not recreate identical types or findings.

Use the deterministic `pageId` in the report draft plus `caseId`, bounty and constituent proposal IDs as matching evidence. Before first creation, search existing reports by these identifiers and exact/normalized title. A compatible legacy report may need adoption rather than creation. Before updates, read the existing page, comments, human decisions and currently indexed operations. Preserve user material; propose only changed report-owned fields. Local deterministic IDs alone do not prevent duplicates against a pre-existing report under a different ID.

Keep the submission title in the page name only, with no repeated body heading. Use plain, kind status language and a readable UTC date; comparisons that need hours use explicit UTC timestamps. Precise timestamps and assessment codes stay in the internal record. Tell the reader: “Open each review in the table below to see the full details, including the original statement, the issue and supporting sources.” Open each linked finding during delivery verification and check that its complete content and evidence are readable. Do not imply acceptance, payout or a completed review from an unfinished assessment.

The recipient report has the six agreed comparison fields and full text. Keep internal coverage/requirement notes in the case JSON; do not append them beneath the recipient table. Native tables may show a mandatory Name column or shortened previews; complete finding pages/blocks must expose the full original, exact excerpt and supporting evidence. Keep all per-item outcomes and unresolved checks in the internal case record, with concise recipient feedback. Pending submissions link to real governance proposals and captured values; never invent a live entity page.

Prepare publication ops through geo-publish and show the concrete Crypto pilot draft before requesting its final gate. Standing authorization, if provided, must identify report-only destinations/scope; it does not authorize curator proposal execution, awards or messages. Store submitted report proposal IDs separately from indexed report IDs and verification receipts. After an unknown write outcome, inspect proposal/report state before retrying. Reuse the existing case mapping and verify every changed field, proposal references and evidence after indexing. Mark delivery verified only on successful readback; failures retain the prior receipt and exact retry blocker.

The review runner produces drafts only. `scripts/report-ops.mjs DRAFT_JSON DELIVERY_PLAN_JSON OUT_JSON` can build a create-only GRC-20 dry-run package using the installed geo-publish SDK (`GEO_CM_DIR`). It cannot sign/upload/broadcast. Supply current discovery, duplicate/schema receipts, exact item/proposal and citation target identities; reuse the existing Review finding model after inspecting its schema. The Crypto pilot explicitly proposes adding the existing Issue property to that type in the datasets perspective. Native tables have mandatory Name/previews; complete finding blocks retain all six fields. A captured pending citation target is a proposed-content reference, not an indexed page; preserve its direct source/proposal URL. Updates require a live preservation/merge plan through geo-publish; the create helper deliberately refuses them. An agent must complete the geo-publish authorization and readback workflow for delivery. Until a real pilot write/readback succeeds, do not describe this package as unattended report delivery.

Keep the editor-only selection/points summary in a separate local/internal artifact. Do not place it in a shared report, finding page, table, Notion body or curator message; hiding it in a collapsed block is not sufficient. Publish only the recipient Markdown/findings, not the internal review JSON.

Before final report delivery, require `reviewReadiness(case).complete`. An unresolved material submission decision stays in the investigation queue; it cannot be published as a final review. The operation helper checks this independently of draft labels.
